# STFspec informal specification: design overview

*Status: draft informal specification, updated 2026-09-29. Pin: `tests-zkevm@v21.0.0` @e1a316a0 (`reference.toml`). Architecture: `STFSpec/informal/ARCHITECTURE.md`. No Lean definitions exist yet: this is the specification the implementation will follow.*

This document composes the 23 spec guidance documents in [`modules/`](modules) into one end-to-end design. It records how the modules fit together, which seams are resolved, which are provisional, and what is still missing.

The review adds [COMPOSITION](COMPOSITION.md), the conditional end-to-end correctness argument and canonical adapters; [REVIEW](REVIEW.md), evidence and implementation gates; [REFERENCE-RECORDS](REFERENCE-RECORDS.md), generated source field layouts; and [contracts.toml](contracts.toml), shared declaration ownership/proof imports. Every module's §7 includes its claim, premises, argument and open obligations.

**Current evidence** (read alongside the spec guidance documents, which cite it on their navigation lines): the interface findings F1–F20, whose dispositions are recorded in [`STFSpec/informal/DECISIONS.md`](DECISIONS.md) §3.

## 2. End-to-end: from input bytes to output bytes

```mermaid
sequenceDiagram
    autonumber
    participant G as EthStateless
    participant C as EthCodec / EthHash
    participant B as EthBlock (EthFork config)
    participant W as EthStateWitness / EthStateCommit / EthCommit
    participant S as EthState (overlays)
    participant R as EthVmRunner
    participant I as EthVmInstructions / EthVmCore
    participant P as EthPrecompiles
    G->>C: decode schema id + SSZ StatelessInput (O1 on failure)
    G->>C: hash_tree_root(NewPayloadRequest) → request root (O2 if it fails)
    G->>G: validate witness headers: RLP, contiguity by keccak, non-empty (O3/O3a)
    G->>W: build node DB and code DB, PreState rooted at parent.state_root
    G->>G: execute_new_payload_request: block hash, versioned hashes, requests
    G->>B: executeBlock with Amsterdam configuration
    B->>B: validate_header against the parent (incl. excess blob gas, EIP-7918)
    loop system calls, then each transaction
        B->>S: check_transaction, sender recovery (public-key hint, O5)
        B->>R: process the message call with a TxState over the BlockState
        loop frame loop (candidate fuel = Φ + 1; proof open)
            R->>I: step → next frame / halt / child request
            I->>S: reads/writes through overlay laws (reads recorded)
            R->>P: precompile address → table entry
            R->>R: child request → recursive run → resume (snapshot/revert)
        end
        B->>S: settle gas, receipt, BAL builder update, fold tx into block
    end
    B->>S: withdrawals, requests, BAL build/hash/validate
    B->>W: PreState.stateRoot(BlockDiff in first-write order) (eager decode, O4)
    W-->>B: post-state root (incremental rehash of dirty paths)
    B-->>G: ok, or an explicit BlockError/TxError
    G->>C: encode 43-byte result (O10 true / O3–O7 false / O1–O2 zero sentinel)
```

Each step is owned by exactly one module; the arrows are the seams in §3.

## 4. Cross-module correctness

[COMPOSITION](COMPOSITION.md) gives the argument, the proof dependency diagram and the premise discharge table. Its state induction covers reachable read-before-write, ordered writes, rollback/observation lifetimes, BAL update-before-merge and code authenticity. Its VM induction separates structural termination, semantic gas and the four fuel guarantees. Its directional backend simulation requires full-state progress and succeeds up to an explicit collision. Its final phase analysis gives the exact 43-byte output under the completed error/domain/host contract.

Each module's local argument is conditional. A consumer must establish every provider precondition; the provider must establish every promised postcondition. Linearity is a compiled cost discipline rather than a premise of Ethereum semantic soundness. Coverage establishes one source owner, not one implementation or a correct implementation. External chain anchoring, fork activation and chain-ID trust remain consumer obligations.
